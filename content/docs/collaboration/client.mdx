# Client hooks

`@adonis-agora/collaboration-client` brings collaboration to a React frontend. It is **engine-agnostic**: the server tells it which engine a document uses, and it picks the right transport — Hocuspocus, PartyKit, PartyServer or the Automerge protocol — without the UI knowing.

## Provider

Wrap your app once. `baseUrl` is **optional** and defaults to the current origin — the common case where Adonis serves the frontend too. Pass it only when the library lives on a separate host.

```tsx
import { CollaborationProvider } from '@adonis-agora/collaboration-client'

<CollaborationProvider>
  <App />
</CollaborationProvider>
```

## Document sessions

`useCollabDoc` connects to a document and returns the shared `Y.Doc` plus connection status:

```tsx
const { doc, status, error } = useCollabDoc({ docName: 'researches/42/writing' })

// status: 'connecting' | 'connected' | 'disconnected' | 'error'
```

Sessions are cached per document name and survive component unmounts — remount the editor and you reuse the same `Y.Doc`.

### Token flow and reconnects

1. The hook fetches an ephemeral token from `GET {base}/collaboration/token?doc=`
2. It opens the WebSocket with `?token=`
3. Tokens expire: on disconnect, the session tears the transport down and rebuilds it with a **fresh token**, using exponential backoff capped at 15s

## Presence

```tsx
const { peers } = useAwareness({ docName })   // who's online, with cursors
```

Awareness is peer-to-peer (Yjs) — the live cursors of other users. Server-side presence (Redis, cross-instance) answers "how many users across all instances" via `manager.listPresence`.

## Comments and versions

Anchored comments and version control are **REST**, not CRDT state — they live in your database via the server's storage.

```tsx
const { comments, create, resolve, remove } = useComments({ docName, space: 'text' })
const { versions, create: createVersion, restore } = useVersions({ docName })
```

## Editor-agnostic editing

Instead of exposing raw `Y.Doc` everywhere, `useCollabEditor` couples an **editor adapter** to the document — same adapter works on Yjs or Automerge:

```tsx
import { createExcalidrawAdapter } from '@adonis-agora/collaboration-client'

const { state, update, status, peers } = useCollabEditor({
  docName: 'lousas/1',
  editorId: 'excalidraw',
  adapter: createExcalidrawAdapter(),
})
```

| Adapter | Surface |
|---|---|
| `createExcalidrawAdapter()` | Scene (`elements`, `appState`) under a doc key |
| `createTldrawAdapter()` | tldraw snapshot (`records` + schema) |
| `createTextAdapter()` | Plain text under a doc key |

## Automerge documents

Structured Automerge documents can't back a `Y.Doc` (and thus Tiptap/awareness). Use the dedicated hook:

```tsx
const { doc, status, error, change } = useAutomergeDoc({ docName: 'fichas/1' })
change((d) => { d.content = 'edited' })
```

It speaks the AutomergeDriver binary protocol directly: initial full save, CRDT merges of remote payloads, debounced local saves.
