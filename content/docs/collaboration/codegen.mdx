# Codegen

AdonisJS v7 generates code from your application and writes it into `.adonisjs/`. The collaboration package plugs into that system so your documents are **typed in one place and re-used everywhere** — backend, codegen registry and frontend.

## Commands

- `collaboration:init` — scaffolds the base documents directory, migrations (when a database is configured) and the PartyKit worker (`--engine=partykit`)
- `make:collab-document <name>` — generates the shared types for one document type

```sh
node ace make:collab-document researches/writing
# creates app/collaboration/documents/writing_types.ts
```

The generated file exports the document's `docName`, allowed comment **spaces** and **anchor kinds** — the single source of truth that both your `authorize` logic and your frontend comments UI import.

## The typed registry

A second, larger payoff: an Assembler `init` hook (registered by `configure`) scans `app/collaboration/documents/` and generates `.adonisjs/collaboration/documents.ts`:

```ts
import type { CollabDocumentName } from '.adonisjs/collaboration/documents.js'

function open(name: CollabDocumentName) { /* autocomplete + exhaustiveness */ }
```

`CollabDocumentName` is a union of every document name in your app. It refreshes on the same lifecycle as the rest of AdonisJS codegen — `node ace codegen`, the dev server, tests and the production build. Add a document, and every call site narrows automatically.

> **Why generate instead of a hand-maintained registry?** A central list goes stale the moment someone adds a document without editing it. Codegen derives the list from the files on disk — the same reasoning the framework uses for controllers and transformers.
