An **Agora Hub** is an ordinary AdonisJS app that runs every Agora library in
`topology: 'control-plane'`. Your other apps keep running their own code and switch the same
libraries to `topology: 'tenant'`: they send traces to the Hub, read their config and flags from
it, ask it for keys and tokens, and let it coordinate their workflows.

There is no Hub package. The Hub is configuration: the same libraries you already run, pointed at
each other.

```
                     hub.example.com
              ┌──────────────────────────────┐
              │ authkit-server   (issuer)    │
              │ telescope        control-plane│
              │ durable          control-plane│
              │ flags            control-plane│
              │ config           control-plane│
              │ crypto           control-plane│
              │ one login · one console      │
              └──────────────▲───────────────┘
                 tokens, traces, config, keys, runs
          ┌──────────────────┴──────────────────┐
   app-a.example.com                    app-b.example.com
   every lib: topology 'tenant'         every lib: topology 'tenant'
   authkit-client (login via Hub)       authkit-client (login via Hub)
```

## When to use one

Use a Hub when you run **two or more AdonisJS apps** that share people, operators or data:

- the same users sign in to several apps;
- you want one console for every app's traces, workflows, flags, config and keys;
- one app calls another, and you want those calls traced, authenticated and encrypted without
  writing any client code;
- you want one place to rotate a secret, flip a flag or pause a schedule for every app.

Keep a single app `standalone`. A Hub adds a service, a database and a network hop; with one app
it buys you nothing.

## What moves to the Hub

| Library | Standalone (today) | On the Hub (`control-plane`) | On each app (`tenant`) |
| --- | --- | --- | --- |
| [AuthKit](/docs/authkit) | each app is its own IdP, or one app is the IdP for the others | `authkit-server`: the issuer, accounts, clients, signing keys, consoles' login | `authkit-client`: an OIDC relying party, and with its `service`, every library's tenant URL, token and partition, and calls between apps |
| [Telescope](/docs/telescope) | each app stores and shows its own entries | stores every app's entries, Fleet, health, alerts, service discovery | records as usual, sends entries in the background, optional local copy |
| [Durable](/docs/durable) | each app owns its runs, schedules and worker | owns the store, the schedules, recovery and the console | runs its steps; owns no store |
| [Flags](/docs/flags) | each app owns its ruleset and events | owns the ruleset, the console, events and sinks, OFREP | evaluates in memory from a ruleset snapshot, sends events |
| Config ([`@adonis-agora/config`](https://github.com/DavideCarvalho/adonis-agora-config/tree/master/docs)) | values in each app's env | every app's versioned config and sealed secrets, history and audit | fetches its scope at boot, keeps a snapshot, hot-reloads what may reload |
| Crypto ([`@adonis-agora/crypto`](https://github.com/DavideCarvalho/adonis-agora-crypto/tree/master/docs)) | each app holds its own keys | holds every key, enforces capabilities, audits every call | calls the same operations over HTTP; holds no key material |

Each library moves on its own. An app can be a telescope tenant and still own its flags; another
app can stay fully `standalone` next to the Hub. Leaving an app out is a normal, supported setup:
`standalone` stays the default in every library.

The Hub is one way to arrange the control planes, not the only one: any of them can run as its own
service, and a control plane can itself be a tenant of another one. See
[Composing control planes](/docs/agora-hub/control-planes).

## What stays in each app

- Its own database, its own business tables, its own routes and controllers.
- Its own Redis for sessions, cache and queues (the Hub has its own).
- Its own MCP endpoint (`/mcp/agora`); the Hub signs MCP clients in.
- Its own `APP_KEY` and every bootstrap secret (see [Secrets](/docs/agora-hub/secrets)).

## The guide

1. **[Building the Hub](/docs/agora-hub/building)**: every control plane in one app, one database
   with a schema per library, one login in front of every console.
2. **[Composing control planes](/docs/agora-hub/control-planes)**: the Hub or separate services,
   one issuer and the capabilities each app needs, finding every control plane from the issuer,
   one-line tenant configs with `authkit-client`, and calls over the private network.
3. **[Deploying it](/docs/agora-hub/deploying)**: a service, its database and Redis, a domain.
4. **[Migrating in phases](/docs/agora-hub/migrating)**: observability, then config and crypto, flags,
   workflows, and identity last, each with a go/no-go and a rollback.
5. **[Identity](/docs/agora-hub/identity)**: serve the accounts you already have from the Hub, then
   make it the issuer for every app.
6. **[Calls between apps](/docs/agora-hub/calls-between-apps)**: traced, authenticated and encrypted
   `fetch` between apps, with no new API.
7. **[Who records what](/docs/agora-hub/observability)**: each event recorded once, under the app it
   belongs to, and which apps each viewer sees.
8. **[Encrypting user data](/docs/agora-hub/encrypting-user-data)**: a key per person on the Hub,
   encrypted columns, and forgetting a person on account deletion.
9. **[Secrets](/docs/agora-hub/secrets)**: what goes in the Hub's config server and what stays in
   the platform's environment.
10. **[Pitfalls](/docs/agora-hub/pitfalls)**: a checklist of what goes wrong in practice.
