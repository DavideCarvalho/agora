For Brazilian payment flows, a charge and its fiscal note (NFe/NFSe) are **two different
problems** — and this library keeps them two different providers. The payment goes through
the gateway (Asaas, Woovi, …); the invoice goes through a fiscal provider (Focus,
Tecnospeed, …). The `invoice` option on a charge call **attaches** them: pay via Pix, emit
the note via Focus, in one call.

## Requesting an invoice

The `invoice` option on `charge`, `createSubscription` and `createCheckout` accepts three
shapes:

```ts title="app/services/checkout_service.ts"
// 1. Default invoice provider (config.invoice.default)
await payments.driver('pix').charge({
  customerId: 'cus_x',
  amount: 1990,
  invoice: true,
})

// 2. A named invoice provider — payment via woovi, note via tecnospeed
await payments.driver('pix').charge({
  customerId: 'cus_x',
  amount: 1990,
  invoice: 'tecnospeed',
})

// 3. Per-charge overrides for the named/default provider
await payments.driver('credit_card').charge({
  customerId: 'cus_x',
  amount: 1990,
  invoice: {
    provider: 'focus',
    service: { description: 'Software license', code: '1.01' },
    tax: { iss: 5 },
  },
})
```

The charge succeeds or fails on its own — invoice emission is best-effort from the
gateway's perspective, resolved right after the payment is created.

### The payer's fiscal data

The invoice recipient defaults to the customer's data. For a card checkout, `card.holder`
(`cpfCnpj`, `name`, `email`) is the fallback, so a transparent checkout that also wants a
fiscal note doesn't restate the holder:

```ts title="app/services/checkout_service.ts"
await payments.driver('credit_card').charge({
  customerId: 'cus_x',
  amount: 1990,
  card: { token, holder: { name, email, cpfCnpj, ... } },
  invoice: true, // recipient from card.holder
})
```

## What comes back

The emitted invoice is attached to the returned payment as `payment.invoice`:

```ts title="app/services/checkout_service.ts"
const payment = await payments.driver('pix').charge({
  customerId: 'cus_x',
  amount: 1990,
  invoice: true,
})

payment.invoice?.number  // '12345'
payment.invoice?.key     // access key (chave de acesso)
payment.invoice?.url     // hosted PDF
```

The same event is also published on the diagnostics bus (`agora:payments:invoice.emitted`)
with `number`/`url`, so receipts and notification flows can react to it without coupling to
the charge call site.

## Invoice providers

`config.invoice.providers` is a named map of provider factories — the same lazy-factory
pattern as payment drivers:

```ts title="config/payments.ts"
invoice: {
  default: 'focus',
  providers: {
    focus: invoice.focus({ token: env.get('FOCUS_NFE_TOKEN') }),
    tecnospeed: invoice.tecnospeed({ token: env.get('TECNOSPEED_TOKEN') }),
  },
  defaults: {
    service: { description: 'Software license' },
  },
}
```

Built-in providers:

- **Focus** (`invoice.focus({ token })`) — NF-e / NFS-e / NFC-e across hundreds of
  municipalities via REST; no SDK dependency.
- **Asaas** emits NFS-e natively — configure automatic emission per subscription in the
  Asaas dashboard; the `invoice` option still works through any configured provider.

The roadmap includes Tecnospeed, eNotas and PlugNotas adapters. Until then — or for any
other provider — custom providers are plain factories implementing the `InvoiceProvider`

</Callout>
