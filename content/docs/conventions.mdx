# Conventions

Every HTTP list an Agora library serves (its console API, admin REST, SDK-facing routes) speaks
one wire format: the one [`@adonis-agora/filter`](/docs/filter) defines. Learn it once and you can
call any of them, with `curl`, `fetch` or the typed builder in `@adonis-agora/filter-client`.

## Filtering

Filters go inside `filter[...]`, one key per field:

| You want | Query string |
| --- | --- |
| One value | `filter[status]=failed` |
| An operator | `filter[createdAt][gte]=2026-01-01` |
| Any of several values | `filter[status][]=failed&filter[status][]=canceled` or `filter[status]=failed,canceled` |
| Free text, when the list has it | `search=ana` |

Each list documents its own fields and the operators each one takes. Bare keys (`?status=failed`)
are not a filter.

## Sorting

`sort` takes a comma-separated list of fields. A leading `-` sorts that field descending:

```
?sort=-createdAt,name
```

A list sorts only by the fields it documents. When its store has one fixed order, `sort` accepts
that order (and its reverse, when the store can read backwards) and nothing else.

## Paging

A list pages one of two ways, never both. Its docs say which.

### Offset: `page` and `size`

`page` is 1-based and defaults to `1`. `size` is the page size; each list has its own default and
cap.

```
GET /payments/api/payments?filter[status]=failed&page=2&size=25
```

```json
{
  "data": [],
  "meta": { "total": 120, "perPage": 25, "currentPage": 2, "lastPage": 5, "firstPage": 1 }
}
```

You are on the last page when `meta.currentPage === meta.lastPage`.

### Cursor: `after` / `before` and `first` / `last`

For feeds and stores that cannot count the matching rows. `first` is the page size going forward
and `after` the cursor to start from; `last` and `before` page backwards, on the lists that support
it.

```
GET /telescope/api/entries?filter[type]=exception&first=20
GET /telescope/api/entries?filter[type]=exception&first=20&after=eyJpZCI6…
```

```json
{
  "data": [],
  "meta": { "nextCursor": "eyJpZCI6…", "prevCursor": null, "hasNext": true, "hasPrev": false }
}
```

Send `meta.nextCursor` back as `after` for the next page, until it is `null`. Cursors are opaque:
pass back the ones the server gave you, never build or parse one. A list that only pages forward
always answers `prevCursor: null` and `hasPrev: false`.

### Other keys in the answer

Rows are always under `data`. A list may add top-level keys next to `data` and `meta` for side data
that covers the whole list, such as durable's `statuses`. Small lists that never page answer
`{ data }`.

## Errors

A request the list cannot honour answers `400` instead of being ignored:

- a `filter[...]` field the list does not have, or an operator that field does not take;
- a `sort` field outside the list's sortable fields;
- a cursor the server did not issue.

## Building it in code

- **Calling a list**: the [client builder](/docs/filter/guides/client) writes the query string
  (`.where()`, `.sort()`, `.page()`, `.after()` / `.first()`) and types both envelopes.
- **Serving a list from Lucid**: [pagination](/docs/filter/pagination) covers offset and keyset
  (cursor) pages, and the `offsetPage` / `cursorPage` helpers.
- **Serving a list from any other store** (an API, a cache, an in-memory array): see
  [custom backends](/docs/filter/guides/custom-backends#serving-the-list-over-http).

## Not a list

Two surfaces keep their own shape on purpose:

- **MCP dev tools** on [`/mcp/agora`](/docs/agent/dev-tools) take `limit` and answer
  `{ items, next }`; pass `next` back to page.
- Filter's **`groupByCount`** facets take `groupByCount[limit]` and `groupByCount[offset]`.
